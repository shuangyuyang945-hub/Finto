# Finto 一页POC方案

> 方案版本：v1.0  
> 试点主题：把分散的项目要求整理成可追溯、待负责人确认的交付草稿  
> 产品阶段：单机本地POC，不作为多人生产系统承诺

## 1. 客户问题与目标

项目要求、截止日期和验收标准散落在不同资料中，并可能在执行期间变化。项目负责人需要反复查找和比对，容易漏掉当前有效要求；直接让AI修改正式交付物又会带来越权、错误版本和不可追责风险。

本次POC只验证一个核心假设：

> Finto能否在不绕过负责人的前提下，把本次明确授权的资料整理成带字段级依据的候选，并帮助负责人更快创建一份可追溯的正式草稿？

## 2. 试点使用者与责任人

| 角色 | 责任 |
|---|---|
| 项目负责人 | 选择项目、确认本次授权资料、决定接受/修改/拒绝候选 |
| 交付负责人 | 执行已确认的交付任务并提交成果 |
| 验收负责人 | 确认正式草稿及后续验收状态 |
| Finto | 冻结任务合同、生成候选、校验来源、保存审计；不替代业务决策 |
| POC负责人 | 准备去标识化案例、组织试用、汇总验收证据 |

POC启动前需要客户明确指定项目负责人和验收负责人；未指定时不进入真实业务使用。

## 3. 输入、权限与数据

- 3个去标识化的项目资料案例；
- 每个案例只包含本次交付所需的资料，不导入员工私人账号或未授权文件；
- 项目负责人逐次选择`allowed_source_ids`；
- AgentJob冻结`action`、`instruction`、授权来源、禁止范围和请求合同；
- 资料停用、删除或不在授权快照中时，结果必须被拒绝。

## 4. 本次范围内

```text
创建或选择active Project与当前Cycle
→ 添加或选择项目资料
→ 冻结本次授权并运行零Token或AI任务
→ 生成结构化候选、字段级证据和待确认信息
→ 系统校验used/evidence/checked source IDs
→ 项目负责人原样接受、修改后接受或拒绝
→ 被接受内容创建draft Revision
→ 验收负责人确认后交给执行负责人
```

## 5. 明确不包含

- AI直接修改正式Deliverable或旧Revision；
- 自动统一延期、自动验收或自动改变业务状态；
- 自动读取所有网盘、群聊或知识库资料；
- 多Agent、全量向量RAG、外部消息通知；
- 多人账号、远程部署、企业级并发和身份鉴权；
- 依据3个案例宣称已经达到生产可用水平。

## 6. 运行方式

| 模式 | 适用条件 | 成本与边界 |
|---|---|---|
| 零Token本地解析 | 资料中有明确的阶段成果、交付时间、验收要求等字段 | 不调用模型；只提取明确内容，不猜测 |
| AI模式 | 表达分散、需要语义理解 | 使用客户配置的OpenAI-compatible服务；可能产生费用，输出仍需校验和人审 |

系统不从零Token模式自动切换到AI模式。模式由负责人明确选择。

## 7. 成功指标

3个案例全部记录原始输入、候选、证据、人审决定和正式输出，并按以下指标验收：

| 指标 | 通过条件 |
|---|---|
| 业务可用性 | 至少2/3候选被负责人评为“可直接采用”或“只需小改” |
| 结构完整性 | 3/3结果通过结构和必填字段校验 |
| 来源授权 | 未授权或不可用来源被引用次数为0；授权违规必须返回403 |
| 证据可追溯 | 每个被采用字段能回到`source_id`、locator和excerpt |
| 不确定性诚实 | 资料未说明的内容进入待确认信息，不伪造成事实 |
| 人工控制 | 人工决定前Deliverable/Revision新增数为0 |
| 版本历史 | 采用后创建新Revision，不覆盖旧Revision |
| 故障可定位 | 未预期500能够用`request_id`定位脱敏日志 |

“2/3可用”只用于决定是否继续下一阶段，不代表生产准确率。

## 8. 时间、停止条件与下一阶段

- 准备：半天，完成3份资料去标识化、角色和授权确认；
- 运行与审查：半天，逐案执行并记录负责人实际修改；
- 复盘：半天，汇总指标、失败案例和范围变化；
- 总周期：不超过2个工作日。

任一情况出现时停止试点，不扩大使用：

- 无法取得合法授权或完成去标识化；
- 正式表在人审前发生写入；
- 系统无法区分当前版本与历史版本；
- 关键字段无法回到来源证据；
- 3个案例中超过1个需要大改或被拒绝。

达标后只进入“小范围真实使用”，先补项目级资料关联、登录身份和多人权限，再讨论远程部署、通知或更多Agent动作。

## 9. 当前证据与尚待验证

### 已有工程证据

- 授权快照、合法运行、人审和draft Revision主链已实现；
- 未授权、停用或删除来源能被拒绝；
- 失败候选保留审计，正式表保持零变化；
- 48条产品自动化测试全部通过。

### 尚待真实试点证明

- 3个独立真实案例的2/3业务可用性；
- 第二名首次用户能否独立理解完整流程；
- 多人环境中的身份、权限和协同；
- 长期运行的成本、时延与稳定性。

当前结论只能是“具备本地受控POC条件”，不能写成“已经生产落地”。
