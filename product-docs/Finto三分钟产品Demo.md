# Finto 三分钟产品 Demo

> 演示目标：在三分钟内证明 Finto 能把本次授权的项目资料变成带依据、待负责人确认的交付草稿，并且不会让 AI 绕过人工责任。
>
> 建议环境：使用内置示例项目资料，选择“零 Token 本地解析”。这样演示不依赖外部模型、网络或 API Key。

## 演示前准备

- Finto 已启动并打开“项目总览”；
- 当前项目处于 `active` 状态；
- 已准备一份包含“阶段成果、交付时间、验收要求”的去标识化资料；
- 待审建议列表和交付清单中没有会混淆本次演示的旧数据；
- 不把尚未完成的干净电脑安装验收、多人权限或生产部署说成已经完成。

## 0:00—0:30｜问题与产品判断

### 讲解

> 项目要求、截止日期和验收标准经常散落在任务书、反馈和聊天记录里，而且会发生变化。直接让 AI 修改正式交付物虽然快，但容易引用未授权资料、覆盖历史版本，也会让负责人失去最后判断权。Finto 的做法是：AI 只生成带依据的候选，正式内容必须由负责人确认。

### 页面动作

停留在“项目总览”，指出当前项目、当前周期和四步路径：创建项目、添加资料、选择本次授权资料、运行并进入待审。

### 要证明的事实

- 一次操作属于明确的 Project 和当前 Cycle；
- 保存到资料库不等于已授权给任务；
- 系统先产生候选，不直接产生正式业务事实。

## 0:30—1:10｜冻结本次任务边界并运行

### 页面动作

1. 勾选本次允许使用的资料；
2. 选择“零 Token 本地解析”；
3. 保留默认任务要求；
4. 点击“冻结本次授权并运行”。

### 讲解

> 这里不是让 AI 随便读取全部资料。系统会为本次 AgentJob 冻结动作、具体要求、允许来源和禁止范围。零 Token 模式只读取资料中明确写出的字段，不调用模型，也不会猜测资料没有写的内容。

### 要证明的事实

- 授权范围是任务级快照；
- 运行方式由负责人明确选择，系统不会偷偷切换到付费模型；
- 合法结果只进入 `awaiting_review`，此时正式 Deliverable 和 Revision 仍然没有新增。

## 1:10—2:05｜检查候选、依据和待确认信息

### 页面动作

进入自动打开的“待审建议”，依次指出：

1. 本次任务能做什么、使用了哪些授权来源、明确不能做什么；
2. 候选交付成果、截止日期和验收标准；
3. 每个字段对应的来源编号、定位和原文摘录；
4. “待补充与确认”中资料没有写清楚的内容。

### 讲解

> 负责人看到的不只是一段 AI 文本。每个候选字段都能回到来源、位置和原文；资料没有说明的负责人或范围会进入待补充与确认，而不是被模型补成事实。系统还会校验实际引用来源是否超出任务授权，未授权、停用或被删除的来源会被拒绝。

### 要证明的事实

- `used_source_ids`、字段级证据和已检查来源都受授权校验；
- 来源越权或失效返回 403，并保留失败审计；
- 失败候选不会写入正式交付表。

## 2:05—2:40｜由负责人形成正式草稿

### 页面动作

1. 选择需要采用的候选；
2. 核对或修改成果名称、交付时间、验收标准、范围和责任人；
3. 查看“准备写入什么”的实时预览；
4. 填写审查原因；
5. 点击采用并创建待确认成果。

### 讲解

> 原样接受、修改后接受和拒绝都是人工决定。负责人提交后，系统才创建新的 draft Revision；原始候选、人工修改和原因都会保留。修改旧成果时也会创建新 Revision，不覆盖旧版本。

### 要证明的事实

- 正式写入发生在人工作出决定之后；
- Deliverable 指向当前 Revision，历史 Revision 保留；
- 接受 AI 建议不等于成果已经确认或验收通过。

## 2:40—3:00｜闭环、边界与下一步

### 页面动作

进入“交付清单”，展示新建的第 1 版、`draft` 状态、负责人、验收负责人、截止日期和版本历史，并指出“确认草稿并交给执行负责人”的下一动作。

### 讲解

> 到这里，来源、任务合同、候选、人工决定和正式版本已经连成一条可追溯链。当前版本适合单机受控 POC；多人登录鉴权、远程部署、项目级资料强关联和长期生产监控还没有完成，不能把这次演示表述成生产落地。

## 演示后的证据清单

| 演示结论 | 可核对证据 |
| --- | --- |
| 只使用本次授权资料 | AgentJob 合同与授权来源列表 |
| 字段可以追溯 | source ID、locator、excerpt |
| 缺失内容没有被猜测 | 待补充与确认列表 |
| 人审前正式表零写入 | 候选状态与自动化测试 |
| 接受后创建正式草稿 | Deliverable、当前 Revision 与人审记录 |
| 历史不会被覆盖 | Revision 编号、current revision 指针与版本历史 |
| 关键风险受到保护 | 48 条产品自动化测试与失败审计 |

## 演示失败时的降级路径

- 外部模型不可用：切换到零 Token 本地解析，不影响核心人审闭环；
- 当前资料字段不明确：换用演示资料，不伪造候选；
- 页面出现 500：记录 `request_id`，按故障定位 SOP 查找脱敏日志；
- 页面已有旧数据：明确指出本次 Job 编号，只演示该任务产生的候选和版本；
- Windows 安装包被 SmartScreen 提示：说明当前安装包尚未完成代码签名，不把它解释为业务逻辑故障。

## 一句话收尾

> Finto 不是让 AI 代替负责人决定，而是把“资料查找、要求整理和证据定位”交给系统，把“是否成为正式版本”的责任留给人。
